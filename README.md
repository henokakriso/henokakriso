<summary><code>HOW THE LIVE DATA ON THIS PAGE WORKS</code></summary>

<p style="color:#8B98A5;font-size:13px">
<strong style="color:#E6EDF3">Instant (per page view, no setup):</strong> the badges, stats cards,
streak and top-languages are generated on-demand by public GitHub-compatible
services (<code>github-readme-stats</code>, <code>streak-stats</code>, <code>github-profile-trophy</code>,
<code>shields.io</code>), which read the GitHub API whenever the image is requested.
</p>

<p style="color:#8B98A5;font-size:13px">
<strong style="color:#E6EDF3">Weekly (GitHub Actions)</strong> — the <code>GITHUB // SYSTEM STATUS</code>
panel and <code>BUILD LOG</code> heatmap are real SVGs committed to this repository by the
<code>live-stats</code> workflow (<code>.github/workflows/live-stats.yml</code>): it queries the public
GitHub API, renders <code>assets/github/system-status.svg</code> and <code>activity.svg</code>, and
commits them. Only public data is used; no secrets are exposed
(the default Actions token with <code>contents: write</code> is used to commit).
</p>

<p style="color:#8B98A5;font-size:13px">
<strong style="color:#E6EDF3">Animations:</strong> hero, timeline, architecture and project-card SVGs use
CSS/SMIL animations inside the SVG files. They are served through jsDelivr because
GitHub does not render repository-hosted SVGs inside <code>&lt;img&gt;</code>. All animations
respect <code>prefers-reduced-motion</code> and degrade to a static image.
</p>

<p style="color:#8B98A5;font-size:13px">
<strong style="color:#E6EDF3">Best-effort sync:</strong> jsDelivr caches files for up to 12 hours, so freshly
refreshed stats may take a few hours to appear on the profile. The README itself
contains no JavaScript and therefore works on any GitHub renderer.
</p>
